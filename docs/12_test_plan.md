# STEP 12 QA 계획

| 시나리오 | 사전 조건 및 입력 | 절차와 PASS 기준 | 증거 |
| --- | --- | --- | --- |
| TC-N-01 로그인 | 초기화한 합성 관리자 | 로그인 제출 → 데이터 관리 이동 → 사용자 식별 확인 | 구현 화면, pytest 판정 |
| TC-N-02 등록 | 인증, 빈 테스트 DB | 이름·설명 등록 → 목록과 DB ID·개수·값 확인 | 화면 및 DB 확인 |
| TC-N-03 수정 | 인증, 테스트 항목 1건 | 항목 선택 → 값 수정 → 같은 ID와 새 값 확인 | 화면 및 DB 확인 |
| TC-EX-01 응답 단절 | 인증, 빈 테스트 DB | 첫 등록의 서버 응답을 브라우저에서 차단 → 같은 폼 재시도 → 최초 ID와 DB 1건 확인 | 응답 차단, 재시도, 건수, 스크린샷 |
| TC-EX-02 특수문자 | 인증, 한글과 따옴표·앰퍼샌드·꺾쇠 포함 문자열 | 등록 → HTTP JSON·DB·화면에서 동일 원문 확인 | 원문 동일 여부, 화면 |
| TC-EX-03 중복 제출 | 인증, 단일 등록 의도 | UI 빠른 클릭과 별도로 등록 키가 같은 동시 HTTP 요청 10건 실행 → ID 단일·저장 1건, 키 충돌·독립 키 검증 | 응답 코드, ID, DB 건수 |

각 테스트는 임시 SQLite와 loopback 앱을 준비하고 종료 시 앱·브라우저를 정리한다. 테스트 데이터는 합성 값만 사용한다. 증거 경로를 지정하면 제어된 로그·결과·스크린샷을 보존한다. Worker가 실행한 시나리오는 실제 선택 결과만 수집한다.

보조 검증은 추적표에서 지정한 권한, DB, 상태 전이, 결과 품질, UI 접근성, 백업·복원과 성능 사례를 대상으로 한다. 장애 전후 비교에서는 테스트와 입력을 고정하고 테스트 전용 대체 동작을 사용한다. 실패 증거가 원하는 판정 지점에서 발생했는지 먼저 확인한다.
