# Admin QA Automation Bot BRD

## 업무 요구사항

| ID | 요구사항 | 업무 수용 기준 |
| --- | --- | --- |
| BR-01 | 인증된 관리자에게 데이터 관리 제공 | 로그인 후 등록·조회·수정 가능, 로그아웃 후 보호 기능 접근 차단 |
| BR-02 | 반복 QA 절차 자동화 | 선택한 정상·예외 시나리오 실행 후 실행 및 개별 테스트 상태 조회 가능. 정상 시나리오 3/3 PASS |
| BR-03 | 실패 원인 판단에 필요한 증거 조회 | 이력에서 실행 시각·선택 시나리오·판정 조회. 재현 대상 3종 모두 수정 전 실패 원인과 증거 위치 확인 가능 |
| BR-04 | 대표 장애 3종 재현 및 복구 | 격리된 로컬 환경에서 3/3 재현. 동일 조건 재실행에서 3/3 PASS 및 전체 회귀 테스트 통과 |
| BR-05 | 실행 및 운영 절차 재현 | Docker Compose 구동과 헬스 체크, CI 필수 검증, DB 백업·복원 절차의 실제 결과 기록 |

## 정량 목표와 판정 증거

| KPI | MVP 목표 | 측정 근거 |
| --- | --- | --- |
| 정상 테스트 통과율 | 100% (3/3) | 로그인·등록·수정의 자동화 판정. 미실행 및 SKIPPED 항목은 통과 수에서 제외 |
| 장애 재현 성공률 | 100% (3/3) | 수정 전 동작에서 예상 실패를 확인하고 로그 또는 화면과 DB 상태 기록 |
| 복구 검증률 | 100% (3/3) | 각 재현 시나리오를 동일 조건으로 재실행한 PASS 기록 |
| 중복 저장 건수 | 재전송·동시 요청 시나리오별 0건 | 동일 등록 의도에 대한 최종 저장 레코드가 각각 정확히 1건인지 조회 |
| 회귀 통과율 | 100% (필수 시나리오 6/6) | 정상 3종과 예외 3종을 수정 후 전체 실행, 추가 필수 검증의 실패·오류·누락 0건 |

성능 목표는 부하 조건과 측정 방법을 설계하는 STEP 13에서 정의한다. 표의 모든 수치는 수용 목표이며 실제 통과율은 구현 및 테스트 실행 후 기록한다.

## 운영 조건

1인 개발과 로컬 검증을 기준으로 관리자 역할 하나, 관리 데이터 유형 하나, QA 시나리오 6종을 제품 범위로 설정한다. 회원가입, 다중 조직, 복잡한 RBAC, 결제·외부 서비스 연동, 대규모 분산 처리, LLM 테스트 자동 생성은 확장 범위다. 외부 배포는 별도 승인 대상이다.
