# STEP 09 보안 설계

- 로그인은 개별 salt를 적용한 `scrypt` 해시와 상수 시간 비교로 검증한다. 계정별 실패 5회 이상이면 60초 동안 재시도를 제한한다. 없는 계정도 더미 해시 비교와 동일 자격 증명 오류를 사용한다.
- 세션 쿠키는 난수 토큰, `HttpOnly`, `SameSite=Strict`, 경로 `/`, 유효 시간 8시간을 적용한다. TLS 환경에서 `ADMIN_QA_SECURE_COOKIE=1`을 사용한다. DB에는 토큰 해시만 저장하고 로그아웃 때 폐기한다.
- 상태 변경은 세션의 CSRF 토큰 헤더를 요구한다. 로그인은 JSON 요청으로 제한하며 출처 헤더가 있으면 동일 출처를 확인한다. 앱과 테스트 인스턴스는 loopback 대상에 바인딩한다.
- SQLAlchemy의 바인딩 파라미터와 필드 스키마로 데이터를 처리한다. 브라우저의 사용자 값은 `textContent`로 표시하며, 템플릿은 자동 이스케이프를 적용한다.
- 초기 비밀번호는 환경 변수 또는 프롬프트로 전달하고 저장소에서 제외한다. 로그에 요청 본문, 쿠키, 토큰, 비밀번호, URL 쿼리를 남기지 않는다.
- 증거 API는 인증을 확인하고 실행 ID와 열거된 산출물 이름으로만 파일을 조회한다. 보고서 루트와 실행 디렉터리 외부 파일은 제공하지 않는다.
- 장애 비교는 pytest 전용 프로세스와 합성 데이터에서 수행한다. 정상 코드의 시작 옵션이나 외부 API에 결함 모드를 제공하지 않는다.

검증 항목은 보호 API의 401과 CSRF의 403, 세션 폐기, 로그인 제한, 쿠키 속성, 허용 문자 보존과 파라미터 바인딩이다. `TC-AUTH-01`, `TC-SEC-01`, `TC-EX-02`에 연결한다.
