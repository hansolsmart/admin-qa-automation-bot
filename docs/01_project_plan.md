# Admin QA Automation Bot 프로젝트 기획서

## 문제와 목표

관리자 시스템에서 로그인, 데이터 등록·수정, 결과 확인을 매번 수동으로 반복하면 누락이 생기기 쉽다. 등록 응답이 끊기거나 사용자가 연달아 제출하면 데이터가 저장됐는지 확인하기 어렵고, 특수문자가 포함된 입력은 저장과 화면 표시를 각각 확인해야 한다.

관리자가 브라우저에서 QA 시나리오를 선택해 실행하고, 이력에서 개별 판정과 증거를 확인하는 1인 MVP 구축. 정상 동작을 먼저 검증한 뒤 격리된 로컬 환경에서 장애 3종의 수정 전후를 동일 조건으로 비교한다.

## 대상 사용자

| 사용자 | 사용 목적 |
| --- | --- |
| 관리자 | 인증 후 데이터를 등록·조회·수정하고 제출 결과 확인 |
| QA 담당자 | 정상·예외 시나리오 실행, 판정 및 실패 증거 확인 |
| 개발·운영 담당자 | 실패 원인 분석, 수정 후 재검증, 로컬 실행 환경 운영 |

MVP에서는 단일 관리자 권한으로 데이터 관리와 QA 실행·조회 제공. 담당자 구분은 업무 관점에 적용한다.

## MVP 범위

- 관리자 로그인·로그아웃, 데이터 등록·목록 조회·수정.
- 정상 시나리오 3종과 예외 시나리오 3종 선택 실행, 상태·이력·판정 조회, 실패 증거 확인.
- 등록 응답 단절, 특수문자 처리 오류, 중복 제출의 수정 전후 증거 확보.
- Docker Compose 로컬 운영, CI 검증, DB 백업·복원 확인, 실행 및 운영 문서 제공.

확장 범위는 일반 사용자 회원가입, 다중 조직, 복잡한 RBAC, 결제, 제품 기능의 외부 서비스 연동, 대규모 분산 처리, LLM 기반 테스트 자동 생성. 운영 환경으로의 외부 배포는 별도 승인 후 수행한다.

## 마일스톤과 완료 조건

| 순서 | 단계 | 완료 증거 |
| --- | --- | --- |
| 1 | STEP 01~04 기획·요구사항·구조·모델링 | BRD·PRD, 요구사항 추적표, 아키텍처·ERD 검토 기록 |
| 2 | STEP 05~13 상세 설계와 개별 검증 | API·UI·인프라·QA 설계, 해당 단계에서 요구하는 모델·마이그레이션·격리된 테스트 검증. 통합 환경에 의존하는 항목은 실행 단계 명시 |
| 3 | STEP 14 정상 기능 구현과 통합 | 정상 테스트 3/3 PASS, API·DB·UI·Worker 통합 및 Compose 구동 결과 |
| 4 | STEP 15 장애 재현과 수습 | 장애 3종의 수정 전 실패 및 수정 후 통과 기록, 회귀 결과, Git 이력 |
| 5 | STEP 16 배포 검증과 결과 보고 | Compose·CI 결과, 성능 기준선, 백업·복원 기록, Runbook·README·최종 보고서 |

선행 관계는 `요구사항 → 데이터 및 API 설계 → 정상 흐름 통합 → 장애 재현 및 수습 → 최종 배포 검증`으로 관리한다. 각 STEP의 산출물과 검증 결과를 기록한 뒤 다음 STEP으로 진행한다.

## 주요 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 설계 반복으로 구현 지연 | 단계별 완료 조건과 MVP 범위 고정. STEP 05·10·12의 코드 산출물은 해당 검증에 필요한 범위로 유지 |
| 장애 검증의 운영 데이터 영향 | 격리된 로컬 환경, QA 실행별 DB와 합성 데이터 사용 |
| 등록 응답 유실·동시 제출에 따른 중복 | 서버의 멱등성 처리와 DB 제약 적용. 응답 단절·동시 요청 각각에서 저장 건수 확인 |
| Worker 중단 또는 SQLite 쓰기 경쟁 | 점유·종료 상태 및 타임아웃 설계. 경쟁 조건 재현과 측정은 테스트 환경에서 실행 |
| 실행 환경 차이 또는 증거 누락 | 의존성 버전, 환경·실행 명령, Run ID, 결과 및 증거 경로 기록 |

## STEP 01 검증 범위

검증 대상은 기획서·BRD·PRD의 필수 기능, 제외 범위, 수용 기준 및 단계별 증거의 일관성이다. 애플리케이션 테스트는 관련 구현이 준비되는 단계에서 실행한다. 장애 재현·복구 및 성능 수치의 현재 상태는 미측정이다.

2026-11-19 PowerShell 문서 검사 6개 통과, 실패 0개. 검사 항목은 산출물 3종, BRD 요구 5건의 PRD 연결, MVP 기능별 수용 기준, 제외 범위 일치, 정량 목표와 측정 상태, 단계별 완료 조건이다. 검증 결과와 후속 단계의 증거 요건은 이 기획서에서 관리한다.
