# Admin QA Automation Bot PRD

## 제품 범위

관리자가 로그인한 뒤 관리 항목을 등록·조회·수정하고, QA Dashboard에서 시나리오를 선택해 실행한 후 판정과 증거를 확인한다. 항목 유형은 MVP에서 하나로 제한한다. 필드와 유효성 규칙은 요구사항·데이터 설계 단계에서 확정한다.

## 필수 기능과 수용 기준

| 제품 요구 | 업무 연결 | 수용 기준 |
| --- | --- | --- |
| 관리자 로그인·로그아웃 | BR-01 | 유효한 자격 증명으로 로그인 성공, 잘못된 입력 시 오류 표시. 로그인 전과 로그아웃 후 보호 페이지 및 API 접근 차단 |
| 관리 항목 등록·조회·수정 | BR-01 | 정상 등록 후 목록에 1건 표시. 수정 후 동일 항목 ID에서 변경 내용 확인 |
| 시나리오 선택 및 실행 | BR-02 | 지원 시나리오 목록에서 하나 이상 선택해 실행 요청. 실행 ID와 상태 확인, 선택한 테스트별 결과 조회 |
| QA Dashboard 및 이력 | BR-02, BR-03 | 실행별 상태와 판정 집계, 결과 상세, 증거 링크 표시. 실행 결과가 새로고침 후에도 조회됨 |
| 등록 응답 단절 복구 | BR-04 | 서버 저장 후 응답을 받지 못한 상태에서 동일 등록 요청을 같은 멱등성 키로 재전송. 기존 항목 결과 회수 및 저장 1건 확인 |
| 특수문자 입력 보존 | BR-04 | 허용하는 따옴표·꺾쇠·한글을 포함한 입력이 저장·조회에서 동일하고 화면에 텍스트로 표시됨 |
| 중복 제출 방지 | BR-04 | 동일 등록 의도의 연속 제출·동시 요청에서 저장 1건 확인. 별도 등록 의도는 각각 정상 처리 |
| 로컬 배포 및 검증 재현 | BR-05 | Compose로 앱과 Worker 구동 및 헬스 체크 확인. CI 결과와 DB 백업·복원 실행 결과 기록 |

## 화면 흐름

| 화면 | 주요 행동 | 상태 피드백 |
| --- | --- | --- |
| 로그인 | 자격 증명 제출 | 입력 오류, 인증 실패, 처리 중 표시 |
| 데이터 관리 | 목록 조회, 신규 등록, 기존 항목 수정 | 빈 목록, 로딩, 저장 완료, 오류, 재시도 표시 |
| QA Dashboard | 시나리오 선택, 실행 요청, 이력 조회, 증거 확인 | 대기·실행 중·종료 상태, 개별 판정, 증거 가용 여부 표시 |

## 기본 QA 시나리오

| 유형 | 시나리오 | 판정 증거 |
| --- | --- | --- |
| 정상 | 로그인, 데이터 등록, 데이터 수정 | 인증 및 화면 확인, DB의 생성·변경 결과 |
| 예외 | 네트워크 단절, 특수문자 처리, 중복 광클 | 수정 전 실패와 수정 후 통과 판정, 저장 건수 또는 입력 보존 여부, 관련 실행 로그·화면 증거 |

장애 재현은 테스트 전용 데이터와 격리된 로컬 환경에서 실행한다. 수정 후 자동화의 회귀 실행과 결과 수집 방식은 STEP 12에서 확정하고, 실제 결과는 STEP 14~16에 기록한다.

## 확장 범위

일반 사용자 회원가입, 다중 조직·복잡한 RBAC, 결제·외부 서비스 연동, 대규모 분산 처리, LLM 기반 테스트 자동 생성. 지원 브라우저 및 성능 수용 조건은 후속 QA 설계에서 정의한다.
