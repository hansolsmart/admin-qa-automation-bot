# STEP 06 비즈니스 로직

| ID | 처리와 트랜잭션 경계 | 검증 |
| --- | --- | --- |
| BL-01 | 로그인 실패 횟수·세션 생성은 계정 확인과 한 쓰기 트랜잭션에서 처리. 로그아웃은 토큰 해시로 세션 행 삭제 | TC-AUTH-01, TC-SEC-01 |
| BL-02 | 항목 등록은 짧은 `BEGIN IMMEDIATE` 안에서 키 확인 → 항목 생성 → 최초 응답 저장 → 커밋 | TC-N-02, TC-DB-01 |
| BL-03 | 수정은 대상 확인과 변경을 한 트랜잭션으로 처리. 원문을 보관하며 바뀐 필드만 적용 | TC-N-03, TC-ITEM-01 |
| BL-04 | 실행 요청 커밋 후 ID를 반환. Worker는 짧은 쓰기 트랜잭션으로 가장 오래된 대기 건을 원자적으로 점유 | TC-RUN-01, TC-WORKER-01 |
| BL-05 | 수집 결과의 누락·중복·형식 확인. 유효한 `FAIL`은 실행 `COMPLETED`와 함께 저장 가능 | TC-RESULT-01 |
| BL-06 | 응답 단절 후 등록 키와 본문을 유지해 재전송. 최초 응답을 반환 | TC-EX-01 |
| BL-07 | 길이·빈 이름·NUL을 검증하고 허용된 특수문자 원문을 저장. 화면은 텍스트로 설정 | TC-EX-02 |
| BL-08 | 같은 키·같은 요청은 재생. 같은 키·다른 요청은 409. 키는 관리자 범위, 본문 지문은 필드 정렬한 UTF-8 JSON의 SHA-256 | TC-EX-03 |
| BL-09 | 점유 토큰과 유효 기간 검증 후 개별 결과와 종료 상태를 한 트랜잭션에 기록 | TC-RESULT-01, TC-WORKER-01 |

조회는 읽기 세션에서 수행하며 외부 I/O와 pytest 실행을 쓰기 트랜잭션 밖에서 수행한다. SQLite의 쓰기 대기 한도 초과는 일시적 `DB_BUSY`로 반환하고 키를 유지한 재시도를 허용한다. 상태 변경은 응답 전달 전에 DB에 커밋한다.
